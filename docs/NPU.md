# Проверка декодера StemgenRT на Hexagon

Полный хребет StemgenRT на QNN HTP использует FP16. На CPH2745 (SM8850, Hexagon V81) ошибка постепенно накапливалась в состоянии GRU. Перезапись формулы обновления в ONNX уменьшила ошибку на музыке, но на тестовом тоне ошибка полного хребта достигла −35 дБFS.

Режим `make_npu_model.py --cpu-recurrent` оставляет GRU, входные признаки и восстановление звука на CPU. Hexagon вычисляет спектральную маску из выхода GRU. Декодер не хранит состояние между шагами. На CPU четыре графа совпали с исходной моделью до −107,5 дБ по относительной RMS-ошибке. Декодер на телефоне прошёл тест с запретом вычислений на CPU для его графа. Блок содержит 1920 кадров при 48 кГц.

В 54-секундном прогоне через ONNX Runtime 1.25.1 и QNN 2.42 RMS-ошибка относительно CPU составила −78,9 дБFS. На четырёх музыкальных фрагментах она была на 57–58 дБ ниже входного сигнала, на тестовом тоне на 53 дБ ниже. После затухания хвоста обе версии выдали нули на тишине.

Обычный режим QNN дал 2,10 мс в среднем и 3,95 мс p99 на декодер против 2,25 мс и 2,75 мс у CPU. В отдельном 8-секундном прогоне режим `burst` дал 0,44 мс в среднем и 0,71 мс p99 против 2,25 мс и 2,97 мс у CPU. Ошибка в этом прогоне была на 58,4 дБ ниже входа.

Эти замеры сделаны в отдельном процессе Android.

## Проверка внутри аудиоэффекта

В локальной сборке `v1.0.60-qnn-test` QNN запустился внутри `audiohalservice.qti` при воспроизведении YouTube с профилем «Фильм». C++ проводит FFT и восстанавливает звук, CPU считает GRU, Hexagon декодирует маску. В первом 50-секундном окне лог показывал `batch=15 npu=1`, три пропуска срока выдачи результата и ноль сбросов. При пропуске на короткое время используется пассивная обработка. Среднее время полной обработки блока в пятисекундных интервалах составило 13–24 мс при длительности блока 40 мс. Энергопотребление в этом прогоне не измерялось.

Для локальной сборки каталогу `vendor/etc/allysound/ally-qnn/` в ZIP нужны `vocals_core.onnx`, `vocals_decoder.onnx`, ONNX Runtime с QNN и библиотеки QNN для устройства. При загрузке KernelSU помещает каталог в `/vendor/lib64/soundfx/ally-qnn/`. При ошибке инициализации используется обычный CPU-сепаратор. При сбое декодера во время воспроизведения последующие маски вычисляются на CPU с сохранением состояния GRU.

Релизный ZIP собирает этот каталог автоматически. KernelSU активирует комплект Hexagon V81 на SM8850. Для проверки CPU на том же устройстве создайте файл `/data/adb/allysound/disable_qnn` и перезагрузите телефон. Чтобы вернуть QNN, удалите этот файл и снова перезагрузите устройство.

## Как повторить

Сгенерируйте четыре ONNX-графа и соберите тест Android NDK для ARM64. Сборке нужны заголовки и ARM64-библиотека из Android AAR ONNX Runtime с QNN.

```sh
python3 tools/make_npu_model.py vocals.onnx models --cpu-recurrent
"$NDK_BIN/aarch64-linux-android35-clang++" -O2 -std=c++20 -static-libstdc++ \
  -I"$ORT_QNN/headers" tools/test_npu_decoder.cpp -L"$ORT_QNN/jni/arm64-v8a" \
  -lonnxruntime -o test_npu_decoder
ffmpeg -i input.wav -c:a pcm_f32le -f f32le -ar 48000 -ac 2 input.f32
```

Поместите исполняемый файл, каталог `models`, входной PCM, `libonnxruntime.so` и библиотеки QNN HTP для архитектуры устройства в отдельный каталог в `/data/local/tmp`. Запустите в этом каталоге из ADB shell.

```sh
export LD_LIBRARY_PATH="$PWD" ADSP_LIBRARY_PATH="$PWD"
./test_npu_decoder cpu models input.f32 cpu.f32
./test_npu_decoder qnn models input.f32 qnn.f32
ALLYSOUND_QNN_PERFORMANCE_MODE=burst ./test_npu_decoder qnn models input.f32 qnn_burst.f32
```

Выходные файлы содержат stereo PCM float32 LE, 48 кГц, с чередованием каналов. Для оценки ошибки вычтите результаты по отсчётам и сравните RMS разности с RMS входа. Параметры QNN описаны в [документации ONNX Runtime](https://onnxruntime.ai/docs/execution-providers/QNN-ExecutionProvider.html).
